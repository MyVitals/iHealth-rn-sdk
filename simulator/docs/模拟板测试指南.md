# iHealth 设备模拟板：App 接入测试指南

本指南面向使用 iHealth iOS SDK（静态库）或 Android SDK 的 App 团队。你不需要真实的血压计、血糖仪等设备：一块几十元的 ESP32‑S3 开发板刷上 SDK 附带的固件，就是一台能被 SDK 扫到、连上、通过认证并应答全部指令的 iHealth 设备，而且能用串口一条命令造出真机很难复现的数据和故障。

适用范围：SDK 包里 `simulator/` 目录的固件（版本见同目录 `manifest.json`）。固件只提供二进制。

---

## 1. 准备

| 项 | 说明 |
|---|---|
| 开发板 | 微雪 **ESP32-S3-DEV-KIT-N16R8**（两个 USB‑C 口的那款）。其他 ESP32‑S3 板子只要 16 MB Flash、带 USB 串口芯片也可以，但板载 RGB 灯脚位可能不同 |
| 线 | USB‑C **数据线**（充电线刷不了） |
| 电脑 | macOS / Linux / Windows，装 Python 3 后 `python3 -m pip install esptool`。macOS 不用装串口驱动 |
| 手机 | 装了你的 App 的 iPhone / Android 手机，蓝牙打开 |
| SDK | iOS SDK 2.16 及以上 / Android SDK 2.16 及以上（具体对应关系见 `manifest.json` 的 `validated_with`） |

一块板子同一时间只服务一部手机；要同时测 iOS 和 Android 就用两块板子。

## 2. 刷固件（一次）

1. 线插在开发板上标 **UART**（或 COM）的 USB‑C 口；标 USB 的口是芯片原生口，不用。
2. 找到串口：macOS `ls /dev/cu.usbmodem*`，Linux `ls /dev/ttyACM*`，Windows 看设备管理器 → 端口（USB Single Serial, COMx）。
3. 刷写：

```bash
cd simulator
./flash.sh                               # 只插了一块板；多块板时 ./flash.sh /dev/cu.usbmodemXXXX
```

Windows 用 PowerShell 直接跑脚本里那条 esptool 命令（串口换成 COMx）。刷完板子自动重启，用串口工具（`screen /dev/cu.usbmodemXXXX 115200`、PuTTY 等，波特率 115200）能看到：

```
=== iHealth KD-5819D BLE simulator === build ...
[ble] advertising as "KD-5819D"  MAC/serial 1020BA6FDAF1  authId "ESP-1020BA6FDAF1"
```

> 新板子出厂自带厂商演示固件（RGB 灯循环变色，串口只打 `50%R / 50%G / 50%B`），刷之前看到这个是正常的。板子记住的机型存在 Flash 里，以后升级固件不会丢。

## 3. 选择要模拟的设备

串口里输入 `model <key>`，板子保存并重启成该设备（约 5 秒）：

| key | 设备 | 类型 | SDK 设备类型 | 内置场景数 |
|---|---|---|---|---|
| `5819d` | KD-5819D | 血压计 | KD5819D | 23 |
| `723se` | KD-723SE | 血压计 | KD723SE | 32 |
| `po3` | PO3（新版） | 血氧仪 | PO3 | 51 |
| `kn550bt` | KN-550BT | 血压计 | KN550BT | 47 |
| `kn550lt` | KN-550LT | 血压计 | KN550LT | 48 |
| `pt3sbt` | PT3SBT | 额温枪 | PT3SBT | 47 |
| `bg1s` | BG1S | 血糖仪 | BG1S | 52 |
| `bg5s` | BG5S | 血糖仪 | BG5S | 82 |
| `hs2s` | HS2S | 体脂秤 | HS2S | 79 |

**设备序列号（MAC）**：模拟板用芯片自己的蓝牙地址，每种设备各不相同，以切机型后开机日志里的 `MAC/serial` 为准，SDK 扫描回调里拿到的 `SerialNumber` 就是它。**App 里不要写死序列号**，换一块板子就变了。

切换机型后，如果 App 之前绑定过这块板子的另一种设备：iOS 先在 App 里解绑 / 忘记设备，必要时关开一次手机蓝牙；Android 偶尔也需要关开一次蓝牙。

## 4. 用你的 App 连接

模拟板对 SDK 来说就是真机，App 侧不需要任何改动：按 SDK 文档正常扫描、连接、认证、调指令即可。

- iOS：`ScanDeviceController commandScanDeviceType:HealthDeviceType_<设备>` → 收到 `<设备>Discover` 通知（`SerialNumber` = 板子 MAC）→ `ConnectDeviceController commandContectDeviceWithDeviceType:andSerialNub:` → `<设备>ConnectNoti` 后用设备对象调指令。
- Android：`iHealthDevicesManager.startDiscovery(DISCOVERY_<设备>)` → `onScanDevice` → `connectDevice` → `onDeviceConnectionStateChange` 为 `CONNECTED` 后用对应的 `Control` 调指令。
- SDK 的 license / 授权流程照常执行，模拟板不影响。

板载 RGB 灯：**蓝闪** 广播中（等手机来连）→ **黄** 已连接、等认证 → **绿** 认证通过、正常收发 → **红闪** 收到校验错误的帧。扫不到时先看灯是不是蓝闪。

注意事项：板子离手机 1 米内；测试时不要同时开着同型号真机；手机上不要同时运行多个会自动连设备的测试 App（后台那个会抢连接）；打开串口会让板子复位一次，App 已连接时不要开关串口。

## 5. 串口命令：造数据、造故障

波特率 115200，命令以回车结尾。`help` 列出当前机型的全部命令。

通用命令：

| 命令 | 作用 |
|---|---|
| `info` | 当前状态、收发计数、设备时钟、全部记录 |
| `scenario list` / `scenario <名>` | 列出 / 切换场景预设（一条命令摆好一整套状态）；`scenario normal` 恢复默认并清掉所有故障注入 |
| `seed` / `clear` | 写一组演示数据 / 清空记录 |
| `time <epoch>` | 设设备时钟 |
| `fw <fff> <hhh>` | 设备上报的固件 / 硬件版本（`fw 210 120` = 2.1.0 / 1.2.0） |
| `fault delay <ms>` | 业务回包延迟（测 SDK 超时） |
| `fault noreply <hex>` | 某条指令不应答 |
| `fault badcks 1` | 回包校验和改坏 |
| `fault drop <hex> [n]` | 第 n 次发完某指令后断开蓝牙 |
| `fault fe 1` / `fault badr1 1` | 认证失败的两种方式 |
| `fault clear` | 清掉全部故障注入 |
| `adv on|off [秒]` | 开 / 关广播（关 = 设备睡眠或没按键；`adv off 30` 30 秒后自动恢复） |
| `disconnect` / `reboot` | 主动断开 / 重启 |

各机型专属命令（节选，`help` 有全表）：

| 机型 | 常用 |
|---|---|
| 血压计（5819d / 723se / kn550bt / kn550lt） | `add <组> <高压> <低压> <心率> [flag]` 加一条记录（flag：`80` 心律不齐、`40` 体动、`20` 袖带）、`batt <0-100>`、`pkt <n>` 每包条数；KN-550BT `proto 21|22` |
| PO3 | `add <spo2> <pr> <pi×10>`、`finger in|out`、`charge 0|1`、`rt <spo2> <pr> <pi×10> [hz]` 实时波形 |
| PT3SBT | `measure <温度>`、`unit c|f`、`live <秒>|off` 实时温度、`batt` |
| BG1S | `bg strip in|out`、`bg blood`、`bg result <mgdl>|low|high`、`bg error <hex>`、`bg run` 一键插条→滴血→出结果 |
| BG5S | `b5 strip in|out`、`b5 blood`、`b5 result <mgdl>|low|high`、`b5 run`、`b5 charge in|out`、`b5 rec add <mgdl>` / `b5 rec fill <n>` / `b5 rec clear` 离线记录、`b5 clock …` 设备时间、`b5 busy on|off` |
| HS2S | `weigh <kg> [体脂%]`、`weigh_fail over|unstable|timeout`、`user list|add|clear`、`rec add <槽> <kg>`、`hr <n>`、`err <hex>` |

日常测试优先用场景（`scenario list`），单条命令用来微调。常见场景名各机型基本一致：

| 场景 | 板子行为 | 你的 App 应该 |
|---|---|---|
| `normal` | 默认数据，设备固件 1.0.0 | 全流程通过 |
| `empty` / `full` | 0 条 / 满量离线记录 | 条数一致，大数据量分包收齐、进度正确 |
| `fw_old` / `fw_new` | 设备上报旧 / 新固件版本 | 版本显示正确，功能不受影响 |
| `auth_fail` / `auth_badr1` | 认证失败 | 提示连接失败，不卡死、不崩溃 |
| `no_reply_*` | 某指令不应答 | 对应功能超时提示，其他功能正常 |
| `slow_2s` / `slow_4s` | 回包延迟 2 / 4 秒 | 2 秒正常；4 秒走超时分支 |
| `bad_checksum` | 回包校验错 | 丢包后超时提示，不崩溃 |
| `drop_after_auth` / `drop_mid_*` | 认证后 / 传输中断开 | 收到断开，传输中断有正确提示，可重连 |
| `badtime` / `extreme` / `clock_skew` | 非法时间、极值、设备时钟错 | 时间兜底、极值不崩、对时后纠正 |
| `lowbatt` / `error_state` / `charging` | 低电 / 设备错误 / 充电 | 状态提示正确 |

## 6. 建议的测试流程

把设备相关的测试分成四步做，每一步都用上一步的产物：

### 6.1 冒烟（每个设备 10 分钟）

`scenario normal`，用 App 走一遍：扫描 → 连接 → 认证 → 同步 / 测量 → 断开。看三样东西：App 界面、App 日志、板子串口日志（`info` 和收发计数）。通过了再往下。

### 6.2 数据用例

按产品需求列数据用例，用串口造出来：条数（`empty` / `full` / 手动 `add`）、时间（`badtime`、`time`、`clock_skew`）、极值（`extreme`）、单位（PT3SBT `unit c|f`、BG5S `b5 unit`）、离线与在线数据的合并与去重。每条用例记录：场景或命令、预期、实际、截图、串口日志。

### 6.3 健壮性用例

真机做不出来、模拟板一条命令就有：认证失败、指令不应答、回包延迟、校验错、认证后断开、传输中断开、设备睡眠（`adv off`）、低电、充电。重点看 App **不卡死、不崩溃、提示正确、可重试**。

### 6.4 回归与自动化

- 把 6.1–6.3 整理成清单，每次 SDK 升级或 App 发版前跑一遍；固件版本随 SDK 包更新（`manifest.json`、`CHANGELOG.md`）。
- 自动化思路：用一个脚本通过串口下发 `scenario <名>`，再启动你的 UI 自动化（XCUITest / UIAutomator / Appium），最后把串口日志和 App 日志放在一起归档。场景与用例一一对应后，整套回归可以无人值守地跑。
- 判读口径统一为三类：**App 缺陷**（App 行为与预期不符，且串口日志证明设备侧正确）、**环境问题**（板子没广播、手机蓝牙缓存、板子被别的 App 抢连——修好重跑，不计入结果）、**平台差异**（iOS / Android 产品定义不同——记录，不算缺陷）。

### 6.5 给其他硬件的建议

同一套方法适用于任何蓝牙设备的 App 测试：先把设备协议整理成可核对的规格（广播、GATT、认证、指令表、错误码）；用开发板实现一个"下位机"，把真机上做不出来的故障做成场景预设；App 侧按"冒烟 → 数据 → 健壮性 → 回归"四步做；最后把场景切换接进自动化。需要新的 iHealth 机型或场景，联系 SDK 组。

## 7. 排错

| 现象 | 处理 |
|---|---|
| esptool 报 `Failed to connect … No serial data received`；串口完全没输出 | 线没插紧、插的是标 USB 的口、或用的是充电线。重插 / 换线 / 换 USB 口；仍不行就按住板上 BOOT 键再按一下 RST，松开 BOOT，esptool 加 `--before no_reset` 重刷 |
| 刷完还是灯循环变色 | 刷写没成功，看 esptool 输出有没有 `Hash of data verified` |
| 串口名变了 | 换了 USB 口或换了板子，串口芯片序列号不同；脚本里改串口名 |
| App 扫不到 | 灯是否蓝闪；`model` 是否是你要的设备；`adv on`；手机蓝牙缓存（第 3 节）；是否另一部手机已连上（灯黄 / 绿）；后台是否有别的测试 App |
| 连上就断 / 认证失败 | 先 `scenario normal` 清掉上次的故障注入；SDK 版本与固件版本是否匹配（`manifest.json`） |
| 串口乱码或长时间无响应 | 拔插板子；反复出现就换板 |

## 8. 版本与范围

- 固件版本 = 开机横幅里的 build 日期；支持的机型、场景数、校验和、验证过的 SDK 版本见 `manifest.json`，变化见 `CHANGELOG.md`。升级固件不会清掉机型选择。
- 未覆盖：设备 OTA 升级、HS1 / HS1S、BG5A、老款 BG5（2017 协议）。发现模拟板行为与真机不一致，或需要新机型、新场景，请联系 SDK 组。
